Spaghetti Brain — Design System Reference

Copy/paste this document into another chat to brief it on this brand's rules and style guide.

Overview

Spaghetti Brain is a live-competition platform for hackathons, coding challenges, design challenges, and quizzes. While a participant works a challenge, the platform tracks tab/window focus and splits the screen into four tracked panes — Challenge (prompt), Code (editor), Review (diff/submission), and Browser (open web research) — so AI-assisted and open-web problem solving is visible rather than hidden.

Built from a written brief only (no codebase/Figma attached), adapting OpenCode's marketing-site design language (monospace-only type, ASCII bracket iconography, hairline-bordered flat sections, one dark "terminal" surface).

Content Fundamentals

  • Voice: terse, technical, slightly deadpan — reads like tool documentation, not marketing copy ("Session tracked. Tab left at 02:14.")
  • Person: direct "you" for product copy/instructions; "we" only when the platform speaks about itself.
  • Casing: sentence case everywhere. No Title Case, no ALL CAPS except single-letter keybind hints (K, Z).
  • Punctuation as UI: ASCII brackets [+] [-] [x] as icons/bullets; a leading > as a prompt marker in code/terminal contexts.
  • No emoji, no exclamation points. Numbers stated plainly ("3 challenges left", not "🎉 3 challenges left!").
  • Vibe: calm, observational, clinical — a proctor's tone, not hype. Matter-of-fact about being watched, never alarming or gamified.

Visual Foundations

  • Palette: warm cream canvas as the only page background; near-black ink as the brand's only "color." One dark surface reserved exclusively for a full-bleed terminal/tracking mockup — never body content. Apple HIG semantic ramp (accent blue, danger, warning, success) is in-product state only; marketing/chrome stays monochrome.
  • Type: 100% monospace, one face for every role. Hierarchy from size + weight only: 38px/700 display, 16px/700 section labels, 16px/400 body, 16px/500 buttons at 2.0 line-height.
  • Spacing: 8px base unit; 96px between major sections, with only a 1px hairline rule marking the seam. No shadows, no heavy dividers.
  • Backgrounds: flat cream, no gradients/photography/illustration/texture. The one dark surface is text-only.
  • Animation: minimal, functional only. State changes snap rather than ease. No decorative motion, bounce, or parallax.
  • Hover/press: flat color shifts only — buttons darken to ink-deep on press. No lift, no shadow gain, no scale.
  • Borders/shadows: zero drop shadows anywhere. Separation is always a 1px hairline border.
  • Radius: two values only — 0px for containers/sections/cards, 4px for interactive elements. Avatars are the sole fully-rounded exception.
  • Transparency/blur: none, except the hairline border's translucent tint. No glass, no backdrop-filter.
  • Cards: flat hairline-bordered rectangles on canvas — never raised, never shadowed.

Font substitution note

Berkeley Mono (referenced in the original brief) is a paid commercial font and wasn't provided. This system substitutes JetBrains Mono from Google Fonts as the closest open metric match.

Iconography

  • No icon system, icon font, or SVG set. ASCII bracket markers ([+] [-] [x] + −) are the icon system — literal monospaced text, never separate icon assets.
  • No emoji anywhere.
  • Small in-product glyphs use literal characters (→ ↻ K Z) rather than SVG icons.
  • The only real visual asset is a pasta-plate glyph used as the brand mark; no other logo exists — do not invent one.

Components (inventory)

  • Forms: Button (primary/secondary/ghost), IconButton, Input, Select, Checkbox, Radio, Switch
  • Feedback: Badge, Tag, Toast, Tooltip
  • Navigation: Tabs, NavBar
  • Surfaces: Card, Dialog, ListRow, FocusBadge, TrackerPanel (4-way split: Challenge/Code/Review/Browser — this product's signature mechanic)

Do's and Don'ts

  • Do render every text role in the mono face. Don't introduce a sans-serif or display face.
  • Do keep cream as the only body background. Don't add gray section bands or gradients.
  • Do use ASCII bracket markers as bullets/icons. Don't replace them with SVG icons.
  • Do reserve the dark surface for one tracking mockup per screen. Don't use it for body content.
  • Do reserve semantic colors (accent/danger/warning/success) for in-product state. Don't use them for marketing CTAs.
  • Do use 4px radius on interactive elements, 0px everywhere else. Don't add shadows anywhere.
